    Variants & Construction Sequences¶

    Two related features study a structure under parallel scenarios and under a staged construction sequence. They share the scenes, and each has its own side panel, opened from the Analysis menu: Variants… and Construction Sequences…. The sequences open together with Support sets, the provisional supports of the phases: two tabs that appear and close at once (the Close button of either closes both). (Variants and sequences also open from buttons in the toolbar.)

    Which one to use¶

    Variant Construction sequence
    What it is A parallel scenario: the same geometry with a subset of active elements and/or supports of its own A chain of phases in time: each phase adds and removes things
    How it is solved From scratch, independently of the others Incrementally: each phase inherits the locked-in forces of the previous ones
    State between them None A member built later does not attract load that was already resisted before it existed
    Use it to Compare alternatives, or one structure with different supports or loads Study how forces build up while a structure is built, propped and struck

    Combining the results of variants with the same geometry is exact. Combining variants with different active geometry is only a comparison (a "what-if"): the mechanically correct way to treat added geometry is a construction sequence.

    The two do not mix. A construction sequence always runs on the base model: it never sees a variant, and a variant's own bars, supports or loads do not reach its phases. A variant, for its part, is a plain model: it carries no sequences and no variants of its own (opening a file whose variant does is reported). With a variant selected in the toolbar, running does not run the sequences: select BASE for that. A variant with bars or sections of its own, in a model that has sequences, says in its Differences from the base box that the sequences ignore it.

    Support sets¶

    A support set is a named, reusable collection of node restraints, for example the provisional supports (props) that a construction phase installs. A variant does not use them: its supports are its own (see below). Define them in the Support sets tab, which opens with Analysis ▸ Construction Sequences…: a list of sets and, for the selected one, an editor of its nodes and the degrees of freedom each restrains (UX, UY, TZ in a plane model, W, θx, θy in a plate model). Nodes can be picked on the canvas or loaded from the selection.

    A set is known by its name, which is also what the phases and their operations call it: Add takes the name typed in the Name box, and Rename changes it, with the phases and operations that use the set following. Delete takes the set out of the phases that use it and removes the operations that named only it.

    A set changes the supports of the phase that uses it, on top of the base's: a node it lists takes the set's restraints (with none ticked, there is no support at that node), and every other node keeps the base's support. So a set of props is just the props, and whatever the base does elsewhere still reaches the phase. A set can also carry springs: a node or element it lists takes the set's spring, and the others keep the base's. The edges of an area object (a rectangle or polygon) are in the set's Edges tab, because their mesh nodes do not exist until the object is meshed: tick This set changes the edges of this object and give each edge, in perimeter order, the degrees of freedom it restrains. A ticked object takes those edges instead of its own and the others keep theirs. (A phase that takes away an edge support needs release_supports off: the reaction of mesh nodes cannot be released yet.) A set that lists a node the model does not have is reported by Model check and when the phase is solved.

    Variants¶

    A variant is a what-if overlay on the working model: the same shared geometry, with a chosen subset of active elements, and supports of its own. The base model is never changed; a variant is a model of its own that stays in step with the base.

    Open Analysis ▸ Variants…. The panel lists the variants (New, Rename, Delete) and, for the selected one:

    • a Description;
    • its Supports: how they differ from the base's (Same as the base, or the nodes that differ), with Reset to base and Copy from… (the base or another variant);
    • All elements: the variant keeps the full geometry and follows any change of the base model automatically. With it off, the Active elements list says which elements the variant has, and it lists the bars, triangles, quads and area objects: Use selection and Remove selection take them from what is selected on the canvas. Selecting a variant draws its active elements in red. An area is in the variant only if it is selected in the list;
    • Seed from the base model: on a new variant, copy all the loads, load cases, analysis cases and combinations of the base, so the variant has an action model of its own. The base's later changes to them reach the variant wherever it has not changed the same thing (see below). Off, it starts clean, and the base's loads and cases never reach it. A variant that has none inherits the base model's.

    Save variant stores the changes. Sync with base reconciles the variant with the current base model and shows what changed (a sync also runs when you select a variant or press Run). Export as .x2d… writes the variant's model as a file of its own.

    Once variants exist, a variant selector appears in the toolbar (the base model and each variant). Picking one shows its model and results in the normal editors and views. To edit a variant's own loads, bars or supports, save it and then switch to it in the selector: they are edited like those of any model, with the support tools on the canvas or the Supports table. The selector stays usable with the Variants panel open, and the panel follows it. While a variant is on the canvas you can edit it; the base is locked against edits from elsewhere (and Use selection / Remove selection, which read the base off the canvas, are available) only while BASE is shown.

    What a variant keeps of its own¶

    A variant is a model of its own that starts as a copy of the base. From then on, what you change on it stays, and what the base changes reaches whatever you did not change: a sync, which also runs when you select the variant or press Run, compares the base now with the base at the last sync and with the variant, item by item. This holds for the supports and springs, the nodes (coordinates), the bars (hinges, section, end nodes…, field by field), the sections and materials, the triangles, quads and area objects (their nodes, section, size and edge modes, field by field; an object is meshed when the variant is solved, on the variant's own model), and the load cases, analysis cases, combinations and loads (a load is compared as a group: what it acts on, in a given case). When both changed the same thing, the variant's value stays, and the Differences from the base box says so.

    A variant can have bars, areas and objects the base does not have. The ids of what is created on the base or on any variant are chosen so that no two differ in the whole file; if an id typed by hand or in an older file names two different things in the base and in a variant, the Differences from the base box says so, opening the file warns, and the variant keeps its own. Sync with base (the explicit one) removes what the variant has and the base does not.

    So a hinge you add to a bar of a variant is still there after the base is edited, and a load case the base gains afterwards appears in the variants that follow its actions. Reset supports discards the variant's own supports and springs, which then follow the base again; Copy supports from… gives it those of the base or of another variant.

    Variant combinations… opens a window that combines the results of several variants with the same arithmetic as a load combination: a list of variant × case × factor terms and an operation (LinearSum, Envelope, AbsSum or SRSS).

    Construction sequences¶

    A construction sequence is an ordered chain of phases. Each phase adds and removes elements, supports and load cases, and the analysis is incremental: locked-in internal forces from earlier phases are carried forward, so a member built later does not attract load that was already resisted before it existed. Open Analysis ▸ Construction Sequences….

    The panel lists the sequences (New, Rename, Delete) and, for the selected one, its Name, the stages of its elements and its phases.

    Stages and scenes¶

    The elements of a phase come in groups, of two kinds:

    • Construction stages. Every bar has a stage number. Select elements, set the Stage and press Assign to to give them that stage. View all stages colours every element by its stage, with a legend.
    • Scenes. Named canvas selections (the Scene menu), used as groups of elements.

    Phases and their operations¶

    The Phases table lists the phases in construction order, with an indicative Time (days) (the age of the phase; nothing reads it yet) and a Name. Selecting a phase previews it on the canvas. Add…, Edit… (or a double-click on the name), Remove, Duplicate, Up and Down manage them, and Save sequence stores the changes.

    A phase is a list of operations, replayed from the top on top of the previous phase. Each is one row of the phase's Operations table, with these columns:

    Column What it is
    Action Add or Remove.
    What Elements (a whole group), Supports (a support set: its restraints and springs) or Loads (a whole load case).
    From, Group For elements: whether the group is a Stage or a Scene, and which one. There is no way to pick individual elements: an operation stays a statement such as "add stage 2".
    Release For supports: when removing one, redistribute its accumulated reaction onto the rest of the structure (see below).
    Factor For loads: a multiplier on the case in this phase, for example 0.5 for half a live load during an intermediate stage.
    Note Free text.

    A stage group is read again from the elements' stage number each time the phase is replayed, so re-tagging elements later updates the phases that use it. A scene group is a snapshot of the scene's elements at the moment the operation was written; editing the phase offers to refresh it.

    Running a sequence¶

    Sequences appear in the analysis cases drop-down in the toolbar, next to the normal cases. Select a sequence and press Run (F5) as usual. Each phase is solved incrementally and its results are stored. A phase selector in the toolbar then navigates phase by phase, for displacements, internal forces and reactions.

    For displacements, the Cumulative Δu box (shown with the deformed and displacement views) chooses between the increment of the selected phase (Δu) and the running total up to and including it. It does not change what is solved, but the choice is kept with the sequence: it survives saving, opening and the Python export.

    Supports and release¶

    A phase can apply a support set to install provisional supports such as props or shores. A phase can have several in force: each Add puts one more after the ones already there, and each changes the supports on top of the base's and of the earlier ones (where two list the same node, the later wins). A Remove takes out the set it names, and only that one. When a set is removed, its accumulated reaction is converted into an equivalent load on the rest of the structure, so the redistribution is captured. Clear Release on the operation to drop the reaction without redistributing it.

    Deleting a support set takes it out of the phases that use it, and removes the operations that named only it. Model check reports a phase operation that names a set which no longer exists.

    Selecting a phase in the panel confines the canvas to the elements built by then, and draws the supports in force in that phase: the base's, changed by the sets it has on.

    The same holds for a removed bar: its locked-in end forces are released onto the remaining structure. Removing a triangle or quad (a wall or a slab element), or a geometry object, does not redistribute what it carried: only its carried state is dropped, so the rest of the structure under-reports until that is added. Plan a sequence so that surfaces are built and not removed.

    For a wall or slab the initial state of the surface elements is carried within one sequence; it always starts from zero at the first phase.

    Sequences in the analysis flow¶

    Each sequence appears as an analysis case of type Sequence in the Analysis Cases panel, read-only. So:

    • sequences appear in the view drop-down with the normal cases and combinations (order: analysis cases, then sequences, then combinations);
    • the Analysis Cases panel has a Status column (solved / pending) for every case, sequences included;
    • sequences, and the variants, are written by the Python script export, so running the exported script rebuilds the model with all its phases and operations.
